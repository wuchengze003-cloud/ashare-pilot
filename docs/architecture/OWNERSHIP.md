# 模块职责与变更权限

本表中的“负责”指对业务含义和生产后果负责，不只是维护某个目录。Agent可以
实施任务，但不能成为合同、策略或风险决定的所有者。

## 系统职责

| 模块 | 负责 | 不负责 |
|---|---|---|
| Research | 点时数据集定义、特征、策略、回测、组合、晋级、冠军、生产目标仓位 | 页面展示、外部数据源凭证、部署 |
| Pyserver | 外部市场数据访问、规范化、缓存、限流、数据日期和质量接口 | 策略排名、仓位、晋级、用户展示 |
| Web | 产品页面、只读查询API、生产产物校验与展示 | 生产策略重算、回测引擎、生产仓位、模型晋级、直接定义数据口径 |
| Ops | 定时编排、任务隔离、验收命令、发布、回滚、运行证据和报警 | 策略公式、参数搜索、股票资格和生产信号语义 |
| Config/未来Contracts | 成本、交易约束、Schema和黄金样例 | 运行数据和实验结果 |

## 决策与审批

| 变更类型 | 可提出 | 可实施 | 必须审核 | 最终批准 |
|---|---|---|---|---|
| 文案、样式、单模块叶子测试 | 任意模型 | 弱模型可做 | 模块审核 | 集成负责人 |
| 模块内部实现，不改变合同 | 任意模型 | 中等或强模型 | 模块测试 + 集成审核 | 集成负责人 |
| 跨模块契约、成本、交易约束 | 强模型 | 强模型 | 双侧契约测试 + 架构审核 | 项目所有者 |
| 策略、参数空间、评估窗口、晋级门槛 | Research或强模型 | 强模型 | 防泄漏和统计审核 | 项目所有者 |
| 股票范围和成员语义 | Research或项目所有者 | 强模型 | 点时覆盖审核 | 项目所有者 |
| 生产状态、执行、部署、回滚 | 强模型 | 强模型 | 端到端与异常演练 | 项目所有者 |

## Agent等级

### 弱模型

只处理客观可验收的叶子任务，例如已有失败测试下的实现、类型、日志、文档或
单个展示组件。默认限制为一个子系统、最多3个文件、约200行差异。

不得修改：

- `docs/architecture/decisions/`
- 未来`contracts/`
- `config/cost-model.json`
- `config/trading-constraints.json`
- 生产赛马、晋级、组合和执行语义
- 股票池、生产runtime、密钥和部署
- 测试或契约以规避失败

### 强模型

可以处理跨文件和跨模块变更，但不能自行改变项目所有者已接受的风险、股票范围
或生产发布决定。共享接口和生产语义必须由强模型完成最终审核与集成。

### 项目所有者

决定产品目标、风险承受、股票范围、生产冠军和发布。模型不得把建议描述成已经
获得业务批准。

## 依赖方向

```text
外部数据源 -> Pyserver/数据产物 -> Research -> 生产信号产物 -> Web
                                      ^
                                      |
                                 Config/Contracts

Ops可以编排每个阶段，但业务模块不得反向依赖Ops。
```

禁止Research依赖Web实现。现有对`web/data/universe.json`的读取已归类为
Legacy耦合，物理拆分时必须移除。AI观察名单如需保留，应通过独立契约提供，
而不是把Web目录当数据服务。任何生产模块都不得依赖`ashare-pilot-legacy`。
