# 系统口径与接口总账

本文件是权威位置的索引，不是把所有业务定义复制到一个文件。每个概念只能有
一个语义权威；生产者和消费者通过版本、日期、哈希和校验样例确认理解一致。

## 契约字段

后续建立机器可校验契约时，每项至少声明：

- `contract_id`与`schema_version`
- 业务含义和单位
- 生产者、消费者和语义负责人
- 权威文件或接口
- `as_of`、`generated_at`与新鲜度要求
- 输入依赖及其哈希
- 向后兼容规则
- 校验命令
- 缺失、过期或版本不匹配时的状态

## 禁止的隐式契约

以下方式不得成为生产实现；拆分时必须删除或改造成上表中的显式契约：

1. Web直接读取`pyserver/cache.db`。
2. Web根据Research内部目录结构寻找未版本化文件。
3. 用空数组推断`HOLD`、`REDUCE_ONLY`或`FLAT`。
4. 用文件修改时间代替交易日和`as_of`。
5. Python和TypeScript分别实现成本或交易规则却没有共同黄金样例。
6. 用README文字代替Schema或测试。
7. 从`ashare-pilot-legacy`读取源码、配置、数据、runtime或部署状态。
8. 把历史报告或回测JSON作为可变的生产输入。

## 变更原则

- 含义改变必须升级主版本，消费者未支持时失败关闭。
- 只新增可选字段可升级次版本，但旧消费者必须有明确行为。
- 已发布产物不可原地改写；修正必须生成新版本并保留审计链。
- 契约变更使用独立任务，不与策略参数、UI重构或部署修改混在一起。
