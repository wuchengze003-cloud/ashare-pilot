# ADR-003：系统异常时允许做什么

- 状态：已接受
- 日期：2026-07-29
- 决策人：项目所有者

## 背景

“空仓”可能表示禁止开仓，也可能表示立即卖出已有仓位。数据过期、适配器缺失
或契约不一致时，盲目卖出和继续交易都可能扩大风险，因此必须用明确状态描述
允许产生的订单。

## 状态

| 状态 | 允许行为 | 禁止行为 |
|---|---|---|
| `ACTIVE` | 按有效冠军生成目标仓位和订单 | 使用未通过门禁的策略 |
| `HOLD` | 保持现状、报警、等待恢复 | 新开仓、换仓、因异常本身盲目清仓 |
| `REDUCE_ONLY` | 使用独立且新鲜的风险与价格数据减仓或退出 | 买入、扩大任何仓位 |
| `FLAT` | 在交易数据有效且可执行时将目标仓位降为零 | 在数据未知时伪造已清仓状态 |

## 状态转换规则

1. 系统从未产生合格冠军：目标状态为`FLAT`，不建立生产仓位。
2. 新冠军缺少精确推理适配器：不激活新冠军。现有冠军只有在自身合同、数据、
   适配器和健康检查全部有效时才能继续`ACTIVE`。
3. 当前冠军被撤销且没有合格替代者：进入`REDUCE_ONLY`，禁止新增风险，并按
   独立有效的退出规则处理已有仓位。
4. 行情、交易日历或信号数据过期：进入`HOLD`。数据过期本身不授权自动全卖。
5. 契约版本、成本、交易约束或产物哈希不一致：进入`HOLD`并阻断新订单。
6. 独立风险开关明确触发且价格与交易状态有效：进入`FLAT`。
7. 任何恢复到`ACTIVE`的转换都必须重新验证日期、冠军、适配器、契约和运行
   产物，不得仅清除错误标志。

## 生产输出要求

每个信号快照必须包含状态、冠军、决策日期、最新完整交易日、契约版本、契约
哈希、原因代码和目标仓位。API中的空信号数组不能单独代表`HOLD`、`REDUCE_ONLY`
或`FLAT`，消费者必须读取明确状态。

## 后果

- 不再使用含义模糊的“异常时一律空仓”描述。
- 无冠军不回退到任何Legacy策略。
- 清仓是明确的风险决策，不是解析错误或数据中断的副作用。
- 后续需要对每个状态和状态转换增加契约测试与异常演练。
