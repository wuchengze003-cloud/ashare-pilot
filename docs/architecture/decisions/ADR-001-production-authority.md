# ADR-001：生产策略由哪个系统计算

- 状态：已接受
- 日期：2026-07-29
- 决策人：项目所有者

## 背景

仓库同时存在Python研究与组合模拟，以及TypeScript网页回测。二者的数据范围、
实现和验证方式不同。如果它们都能声明生产业绩或产生交易信号，页面、回测和
生产可能出现不同答案。

## 决定

1. Python `research/` 是生产策略语义、点时回测、组合目标、晋级和生产信号的
   唯一权威。
2. `web/` 只读取通过版本、日期和哈希校验的生产产物，并负责展示和查询。
3. 旧TypeScript策略、回测、优化器及其历史Dashboard属于Legacy项目。生产
   `web/` 不保留第二套策略引擎；需要诊断时展示Python生成的诊断产物。
4. `pyserver/` 负责市场数据和质量，不定义策略。
5. `ops/` 负责编排和发布，不包含策略或仓位计算。
6. 回测和生产应逐步复用同一套Python策略、成本、约束和组合实现。跨语言只
   共享契约与黄金样例，不复制生产语义。

## 后果

- Web不能因读取方便而重新实现生产排名或仓位。
- Python生产适配器未完成前，即使研究选出冠军也不能激活交易信号。
- 旧Dashboard策略和独立收益曲线不得进入生产构建。
- 跨模块直读数据库和未版本化runtime目录必须在物理拆分时删除或改造，不能
  作为长期兼容路径保留。

## 不采用的方案

- **TypeScript和Python同时作为生产权威**：会造成无法证明一致的双引擎。
- **立即拆成多个微服务**：增加部署和维护成本，不能自动解决语义重复。
- **把Web回测保留为诊断引擎**：仍会形成第二套交易语义和测试负担。
- **直接把Web回测搬入共享包**：会固化重复实现。
