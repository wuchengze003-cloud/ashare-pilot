# ADR-002：股票范围如何确定

- 状态：已接受
- 日期：2026-07-29
- 决策人：项目所有者

## 背景

仓库同时保存中证800点时成分和AI产业链观察名单。二者有大量重叠，但用途不同。
如果把它们当成两个并列交易池，股票可能被重复计算；如果使用今天的AI名单回测
历史，又会引入幸存者偏差。

2026-07-27本地快照中，AI名单有124只，其中105只为当日有效核心观察股；75只
属于当日中证800，30只不属于中证800。重叠是一种成员标签，不代表两份持仓。

## 决定

1. 历史研究基础范围使用交易日当时有效的中证800点时成分。
2. 通用生产策略的基础候选范围使用决策日有效的中证800成分。
3. 最终可交易范围还必须通过数据完整、上市时长、ST、停牌、涨跌停、流动性和
   交易约束检查。
4. 旧项目的`web/data/universe.json`随Legacy冻结，不作为生产接口。需要保留
   的AI观察和分类数据必须经过审计，转换成独立、版本化、带有效期的注释契约，
   不独立授予生产交易资格，也不改变通用策略权重。
5. 同一股票可以同时具有`csi800`和`ai-watch`成员身份，但组合中只有一个证券
   身份，不重复计数。
6. 长鑫科技等暂不属于中证800的AI观察股继续展示和积累数据，但暂不进入通用
   生产策略。
7. 若未来建立AI主题专属策略，必须单独定义点时AI历史成员、研究窗口、基准和
   晋级证据，并通过新的架构决定。不能把今天的AI名单倒灌进历史。

## 目标成员模型

每段成员关系至少包含：

```text
symbol
universe_id
valid_from
valid_to
source
source_version
```

股票名称、板块、AI主题等是证券或分类属性；是否属于某个股票范围是带有效期的
成员关系。生产查询必须显式传入`as_of`日期。

## 后果

- 研究和生产使用同一类点时基础范围，减少宇宙漂移。
- AI名单仍保留产品价值，但不会无意改变生产策略。
- 生产项目不得依赖Legacy路径、今天的静态名单或Web目录来确定历史及当日
  可交易范围。
- 本决定本身不修改现有股票池；物理拆分时再通过单独、可回滚的迁移任务处理。
