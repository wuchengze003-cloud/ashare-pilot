# ADR-004：生产项目与历史项目物理分离

- 状态：已接受
- 日期：2026-07-29
- 决策人：项目所有者

## 背景

当前代码树同时包含旧AI股票池产品、旧规则和多策略实现、TypeScript回测、
历史Dashboard、研究报告及新的生产重建工作。继续在同一项目中用“旧版”“诊断”
或“兼容”标签区分，会让依赖、测试、部署和Agent上下文持续混淆。

这不是一次目录整理，而是两个生命周期、两套产品语义不同的项目。

## 决定

1. 现有GitHub项目`ashare-pilot`保留生产产品身份，本地生产工作区使用
   `/Users/wangjianbin/Desktop/08-独立项目与工具/ashare-pilot-production`。
2. 建立独立的`ashare-pilot-legacy`项目，保存分离前快照、旧策略、旧页面、
   历史报告和必要的可复现说明。Legacy默认只读，不继续部署或产生生产信号。
3. 生产项目不引用Legacy的源码、包、数据库、运行目录、环境变量、部署状态或
   生成产物。Legacy不存在时，生产项目仍必须能够完整构建、测试和运行。
4. 不使用Git submodule、符号链接、相对路径穿越或共享可写卷连接两个项目。
5. 代码只能通过“审计后迁入”进入生产项目：明确当前用途、消除旧语义、接入
   当前契约、补足测试，并以普通生产代码承担维护责任。
6. 历史报告、回测结果、信号快照和供应商原始导出不提交到生产源码树。生产
   审计证据使用不可变运行产物或外部归档，并由manifest记录哈希。
7. 拆分前必须保护原工作区的未提交修改。禁止用重置、清理、覆盖或批量移动
   处理来源不明的改动。

## 身份与历史

生产项目可以保留原Git提交历史，以维持远程地址、部署和用户连续性；代码纯净
度以当前受控源码树、依赖图、构建输入和运行输入为准。Legacy项目保存分离点的
不可变标签和完整旧树，供追溯而非复用。

若未来要求连Git历史也完全隔离，应新建生产远程仓库并重新建立部署信任链；这
是另一项需要显式批准的迁移，不在本决定中自动执行。

## 验收标准

- 生产构建、测试和运行不访问Legacy路径。
- 生产源码不包含旧策略实现、旧回测引擎或旧生产fallback。
- 生产仓无提交的历史运行数据和日期报告。
- CI能阻止禁止路径、禁止依赖和旧策略标识重新进入生产代码。
- Legacy仓有分离标签、来源提交、只读说明和敏感信息扫描结果。
